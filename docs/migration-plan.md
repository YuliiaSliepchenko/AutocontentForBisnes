# План міграції v1 → v2

1. Не запускати сервер під час backup/міграції. Усі операції лише в AutoContent.
2. Створити узгоджену копію SQLite через SQLite Backup API та копію всіх assets.
3. Зберегти SHA-256 файлів і кількість рядків кожної таблиці у manifest.json.
4. Виконати міграцію спочатку на окремій копії backup. Перевірити integrity_check,
   збереження сценаріїв/слайдів/версій/брендів/операцій і незмінність файлів.
5. Лише після успішної перевірки застосувати ту саму міграцію до робочої SQLite.
6. Додати таблиці подій, логотипів і durable generation tasks; не видаляти старі таблиці.
   Старі проєкти лишаються на фактичному етапі; їм не вигадується історія onboarding.
   COVERS_PENDING переноситься в COVER_GENERATION із відкладеним завданням.
7. Міграція транзакційна, повторне виконання безпечне. Запуск застосунку не має
   автоматично мігрувати непорожню стару схему.
8. Rollback: зупинити AutoContent, зберегти поточний data окремо, відновити backup
   у новий каталог і запустити попередній код з AUTOCONTENT_DATA_DIR на цю копію.
   Не видаляти оригінали чи нові файли автоматично.
